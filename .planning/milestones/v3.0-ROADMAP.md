# Milestone v3.0: Auth & Realtime

**Status:** SHIPPED 2026-01-30
**Phases:** 15-17
**Total Plans:** 14

## Overview

Rebuild authentication with atomic profile creation, add realtime sync between coach and student views, and fix timezone handling for correct daily task boundaries.

## Phases

### Phase 15: Authentication Rebuild

**Goal**: Users can securely access their accounts via Google OAuth with role-based routing.
**Depends on**: None (foundation for v3.0)
**Plans**: 6 plans

Plans:
- [x] 15-01: Database trigger + useGoogleAuth role parameter
- [x] 15-02: AuthCallback page for OAuth redirect handling
- [x] 15-03: Role selection UI with direct OAuth trigger
- [x] 15-04: Error pages with logout buttons
- [x] 15-05: useProfile retry + cleanup email/password auth
- [x] 15-06: End-to-end verification checkpoint

**Details:**
- Role selection landing page ("I am a Coach" / "I am a Student")
- Google OAuth only (email/password removed)
- Database trigger `handle_new_user` creates profile atomically
- Role passed via OAuth redirect URL parameter
- Role-based routing from database (not localStorage)
- Emergency logout buttons on error pages

### Phase 16: Realtime Subscriptions

**Goal**: Data changes sync instantly between coach and student views.
**Depends on**: Phase 15 (profile required for user_id filtering)
**Plans**: 5 plans

Plans:
- [x] 16-01: Realtime infrastructure (hook + channels + visibility)
- [x] 16-02: Coach views integration (Dashboard + Calendar)
- [x] 16-03: Student views integration (Home + Calendar)
- [x] 16-04: End-to-end verification checkpoint
- [x] 16-05: Gap closure: Add coach_id filter for realtime

**Details:**
- useRealtimeSubscription hook for declarative subscriptions
- useVisibilityRefetch hook for tab visibility handling
- Realtime channel naming with user scoping
- Coach and student dashboards update instantly
- Denormalized coach_id column for filter efficiency
- React Query cache invalidation on realtime events

### Phase 17: Timezone & Rollover

**Goal**: Time displays respect user's local timezone with correct daily task boundaries.
**Depends on**: Phase 15 (profile.timezone column required)
**Plans**: 3 plans

Plans:
- [x] 17-01: Foundation: DB migration + date-fns-tz + utilities
- [x] 17-02: useTimezone hook + TimezoneSelect + Settings integration
- [x] 17-03: Daily rollover + timestamp displays + verification

**Details:**
- Timezone column in profiles table (IANA format)
- date-fns-tz for timezone-aware date operations
- Browser timezone auto-detection on signup
- Simplified timezone selector (6 US timezones with UTC offsets)
- All timestamps stored as UTC, displayed in user's timezone
- "Today's tasks" respects user's local midnight

## Milestone Summary

**Key Decisions:**
- Profile created with role=NULL, allowing SET once but never CHANGE (AUTH-10 immutability)
- Role passed via redirectTo URL parameter (survives OAuth redirect)
- Card click triggers OAuth directly (streamlined UX)
- Channel names scoped by userId for subscription isolation
- Use invalidateQueries not setQueryData for simpler cache management
- Denormalized coach_id for filter efficiency (realtime requires direct column)
- IANA timezone names as text (handles DST automatically)
- Simplified timezone selector per user feedback

**Issues Resolved:**
- Profile creation race condition (trigger creates atomically)
- Realtime events not delivered (added filter parameter + denormalized column)
- Coach Notes text unreadable on yellow background
- Branding changed from "Routine Craft" to "TeachCoachConnect"

**Issues Deferred:**
- Pre-existing test failure in useProfile.test.tsx (role assertion)
- MultiAuthLogin.tsx unused (could be deleted)
- useGoogleAuth partially duplicated by AuthTabs inline OAuth

**Technical Debt Incurred:**
- Student pages use inline subscriptions instead of useRealtimeSubscription hook (works but inconsistent)
